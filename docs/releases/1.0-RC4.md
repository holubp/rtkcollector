# RtkCollector 1.0-RC4

RC4 supports two explicit NTRIP transports in both Google Play and sideload
builds: TLS with normal Android system trust (the recommended default), and
plaintext NTRIP/TCP. Correction download, sourcetable retrieval and base source
upload use the selected transport without automatic downgrade. Invalid or
untrusted TLS is not supported.

The profile editor warns when plaintext would expose credentials and optional
GGA position. The Home screen shows a compact PLAINTEXT tag beside the relevant
selected route, without treating that choice as a connection error. Legacy
unsafe-TLS profiles require an explicit new transport selection; existing
explicit TLS and plaintext choices remain unchanged. Profiles from versions
before explicit transport selection also require a one-time choice in settings.

The GitHub APK is a stable-key-signed sideload debug testing build, not a Google
Play artifact. The re-released APK has SHA-256
`e453ff4468027c166f3ec8c5d15f28a7bd277adb70a0c8d9fa287badc7363851`
and signing certificate SHA-256
`d8047f43b2748198ae69ff773be13d3aa11c8ac36159dd4e6768a3ac2db3e329`.
Earlier Windows and GitHub debug-signed installs need one reinstall; export
settings and recordings outside app-owned storage before uninstalling. Future
higher-version APKs signed with this key can update in place, pending a device
update test. A signed Play AAB and Play Console Data safety declaration
reflecting optional unencrypted NTRIP transmission are separate publication
gates. Real
Android TLS and plaintext connections have been reported successful by the
owner with this GitHub RC4 APK. RC3 also validated trusted TLS sourcetable
retrieval and plaintext correction intake. Changed UI/failure behavior and
additional paths not specifically reported remain field validation tasks.
Google Play submission is additionally blocked until the optional plaintext
credential/GGA transport is reconciled with Google's User Data policy requiring
modern cryptography for sensitive data in transit.
