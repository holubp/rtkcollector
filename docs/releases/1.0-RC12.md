# RtkCollector 1.0-RC12

Release candidate for deliberate Stop confirmation and improved stop attribution.
Version code: 13. Publication and signed-artifact verification are pending until
the release checklist is completed; RC11 is not replaced or retagged.

## Changes

- Explicit recording Stop controls share a confirmation dialog. Recording
  continues during the initial disabled countdown (default 2 seconds), then
  during the separate enabled confirmation window (default 10 seconds).
- Both countdowns appear inside Confirm. Cancel, Back, outside dismissal,
  expiry, backgrounding or screen recreation leave recording running.
- Advanced settings replaces the logging/performance screen name and retains
  its existing controls. Save app-wide Stop delay (1-60 seconds) and confirmation
  timeout (1-120 seconds); defaults preserve protection on existing installs.
- Service acceptance binds confirmation to the current recording/startup
  session and monotonic deadlines, consumes authorization once, and rejects
  stale/expired requests. Already-confirmed fixed-base transitions retain their
  separate flow. Automatic failure cleanup remains immediate.
- Essential diagnostics distinguish confirmed controls, fixed-base transitions
  and terminal alarm actions, retaining bounded control/request/owner identities
  and stop correlation without credentials or position.

## Evidence Boundaries

The supplied RC11 P30 Pro capture finalized after a USER request. It does not
prove the initiating control or an intentional tap; this release must not be
described as a reproduced fix for that unproven trigger.

The implementation plan records local/host tests and independent review as they
complete. Physical P30 Pro touch/accessibility/background checks remain pending;
CI does not certify device-specific behaviour. Raw recording/storage formats,
receiver commands and NTRIP transport are unchanged by this feature.
