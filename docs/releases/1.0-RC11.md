# RtkCollector 1.0-RC11

Release candidate for recording startup/finalization safety on Android 10 and
newer. This document describes the candidate; the GitHub release record is the
authority for publication, exact source commit, CI and APK verification.

## Changes

- Move receiver/storage initialization, command delays and baud-transition RX
  draining off Android's main thread. Establish the recording foreground
  notification before that work, retaining responsive Query and Stop controls.
- Give startup explicit session/generation ownership. Stop cancels publication
  immediately, then waits off-main for any outstanding initialization to exit
  before closing its writers. A late USB/storage open cannot restart capture.
- Protect session directories from destructive maintenance while their writers
  are opening, including SAF sessions. Preserve partial artifacts on cancellation.
- Exclude competing persistent USB maintenance through startup and finalization.
  Retain canceled late writers and real post-cancellation storage/cleanup errors.
  Do not reopen canceled USB or enable a late mock provider. Retire rejected
  diagnostic cleanup independently after service destruction, and cooperatively
  stop advisory/uploader writers without interrupting SAF sidecar operations.
- Retain genuine startup failures even when Stop overtakes their queued display,
  and serialize bounded NTRIP status updates so stale connecting states cannot
  overwrite newer streaming or failure states.
- Preserve fatal raw-storage failures through additional shutdown/sidecar errors.
  Retain and retry failed USB-handle cleanup rather than permitting a competing
  connection, and preserve final metadata-write exception identity.
- Replace app-private channel-backed append streams with buffered append-mode
  FileOutputStream. Cooperatively cancel capture and receiver-maintenance waits
  instead of interrupting their file IO. Preserve accepted raw bytes at deliberate
  Stop with functional storage; retain explicit genuine storage failures.
- Retain bounded exception/cause classes, artifact/operation and startup stages
  in essential diagnostics, including message-less channel exceptions. Add
  ephemeral process correlation to distinguish UI recreation from process restart.
  Diagnostics remain independent of raw capture and optional Verbose/Debug logging.

## Verification And Limits

Publication requires the full local repository gate, independent source and
specification review, clean-host tests (including Robolectric), both distribution
variants, release lint, pinned native checks/assembly and stable-signed APK
verification. Termux does not execute Robolectric or Android APK assembly.
Unexecuted device/provider obligations remain visible in the verification matrix.
Neither source presence nor a pending receipt constitutes passing evidence.

After installation, test P30 Pro foreground/background Start and Stop during
initialization, USB disconnect/recovery, immediate restart after completed Stop,
and exact raw tail preservation on app-private and SAF storage. Export Minimal
logs to inspect startup/failure/process identity. Vendor kills, power loss and
genuine storage/provider failures can still lose unflushed bytes; the historical
P30 exception class and precise process-kill action were not retained by RC10.

Package `org.rtkcollector.app`, version `1.0-RC11`, version code `12`.
Keep the existing stable sideload certificate. Do not replace RC10's tag or APK.
