# RtkCollector 1.0-RC10

Status: release candidate; device and vendor-specific validation is required.

## Changes

- Fix the RC9 process crash when Stop interrupts a USB reconnect retry sleep.
  An Android bugreport confirms the uncaught capture-worker InterruptedException.
- Request missing USB access from the recording service, once per attachment.
  Recovery does not depend on RtkCollector being the default USB application.
  Denial leaves actionable guidance without repeated consent dialogs; reconnect
  the receiver to try again. Stale replies cannot revive stopped sessions.
- Read platform USB detach events using Android's device extra and register USB
  recovery independently of optional alarm delivery initialization.
- Preserve existing raw/session writers across recovery, pace reconnect attempts
  instead of rereading dead handles, and record minimal recovery-stage diagnostics.
  Receiver-byte recovery, not permission or port open, clears connection loss.
- Warn on Home during recording with acoustic alarms enabled when alarm volume
  is zero/muted or DND is total silence. Other DND modes retain a weaker advisory.
  The app does not change volume, DND or global audio routing settings.
- Keep console Connect/Send unavailable until service-owned receiver cleanup
  finishes, including the interval when the dashboard already says stopping.
- Reject multi-frequency RTKLIB starts for M8T and every supported M8P variant;
  retain UM980 multi-frequency processing. Attempt all owned RTKLIB output
  flush/close operations even when an earlier output operation fails.
- Reject incomplete or inconsistent RTCM1005/1006 reference-position frames
  without throwing from advisory parsing or inventing a missing antenna height.
- Integrate the strict specification framework, with explicit documentation and
  release-process coverage rather than false runtime-code mappings. Approvals
  and exact semantic verification remain separate release prerequisites.
- Bound untrusted NTRIP headers, chunk metadata and payload buffering; keep Stop
  bounded even if socket cancellation blocks. Preserve correction-writer ownership
  until cancellation, intake and callbacks have all quiesced.
- Correct u-blox split-frame handling, Galileo signal bands, time-only fix
  classification and sub-second UTC export. Bound incomplete text buffering.
- Keep u-blox protocol-stall health on elapsed time, independently of wall-clock
  solution timestamps, so a valid frame cannot suppress later stall recovery.
- Keep optional RTKLIB snapshot/status IO off raw capture and scope coordinate
  averaging to one recording, while allowing same-session NTRIP source changes.
- Initialize optional RTKLIB processing asynchronously and retain early input
  within the existing bounded queues. Stop retains ownership until initialization,
  cancellation, status writes and cleanup have quiesced.
- Restore physically present settings families even when backup metadata disagrees;
  publish restored profiles with disabled credential bindings before the separate
  password transaction. Report partial password/activation failures truthfully.
- Validate native engine handle lifetime and contain JNI/native allocation failures.
  Preserve published NMEA/POS output pairs if obsolete backup cleanup fails.
- Harden pinned native-server startup, decoder allocation failure and Stop ordering.
  Propagate a stopped native worker as `FAILED`, without misclassifying deliberate
  Stop. The generated native adaptation checks its pin and supports LF/CRLF input.
- Retain the satellite used-count inference caveat when the boxed bars are populated.

## Release Gates

Publication requires the full repository pre-push gate, independent exact-source
specification assurance, clean-host CI for both distributions and stable-signed
APK verification. Native fault tests run in CI after provisioning the exact
RTKLIB pin and before assembly. The immutable source commit, successful CI runs,
APK checksum and signer receipt belong in the GitHub release record.

Targeted repair evidence includes the integrated 1,232-test app/module run,
114 Unicore tests, 39 RTKLIB tests, 30 native/build checks and 139 assurance tests.
These phase results do not substitute for the final exact-commit gates. Three
Robolectric classes are compile-checked locally and execute on clean-host CI;
Termux cannot supply Android APK assembly or Android device validation.

The owner approved the revised requirements, capability inventory and model 6
baseline on 2026-10-30. The full source audit covers 713 paths and 736
requirement/path pairs; its repair history remains in the tracked plan. Unexecuted
manual/field obligations remain visible rather than being promoted to passing.
RC9's earlier assurance deferral does not cover this release.

Owner-authored work does not require GitHub-level protection or a second GitHub
reviewer; external PRs require trusted-base checks and owner review. This does
not waive local, independent audit, CI or signing gates. No remote repository
settings were changed and no universal protected enforcement is claimed. The
separate Google Play data-policy blocker is not a sideload-release waiver.

Package `org.rtkcollector.app`, version `1.0-RC10`, version code `11`.
The release must retain the existing stable sideload certificate. No changes to
the RC9 tag or its APK are authorized by preparing this new release.

## Device Validation

After installing, test foreground and background USB cable removal/reconnection,
with and without default USB handling and with permission denied then regranted.
Verify Stop during retries, continued byte-exact recording in the same session,
automatic alarm recovery only after actual RX, and no stale callback effect after
Stop/restart. Test mute/volume/DND warnings on the intended phone/headset.
System permission UI visibility on locked/vendor Android remains device-specific.
