# RtkCollector 1.0-RC6

The settings-ownership rebuild retains the RC6 release name and increments the
Android version code to 7 so it can update the earlier RC6 build (code 6).

RC6 fixes the Home mountpoint selector when a settings set fixes the NTRIP
caster but leaves the correction mountpoint changeable. The selected caster no
longer incorrectly locks a mountpoint such as TUBO; users can choose a different
mountpoint before recording. Fixed mountpoints remain locked as configured.

The settings-ownership update makes settings sets select whole profiles rather
than replace fields inside them. A mountpoint uses its own caster, account and
transport; a caster restriction limits eligible mountpoints without substituting
credentials or endpoints. Home, Menu and Start use the same resolution and
selection policies. Re-apply resets active choices without editing shared
profiles or application preferences.

Legacy customizations migrate to explicit profiles while idle, with recoverable
publication and encrypted credential ownership. Ambiguous or unavailable settings
require review rather than guessing. Running recordings retain accepted
configuration; explicit source/mock changes have separate pending and accepted
states. See `docs/user-workflows.md` for policy and shared-profile behavior.

RC6 is a sideload debug testing build. The GitHub release workflow signs its
APK with the stable sideload certificate, verifies the pinned certificate, and
publishes a checksum and signing receipt. Google Play packaging and publication
are separate; this release does not claim Play readiness.

Manual device checks remain: legacy settings upgrade/import with credentials,
SAF reselection, every selection policy and lock combination, shared-profile
edits, pending/retried source/mock changes, fixed-base handoff and raw recording
continuity. Also confirm mountpoint restriction behavior and in-place updates
from an installed stable-key build. Automated gates do not substitute for these
Android/receiver checks.

## Release Gate Decision

On 2026-10-03, the owner explicitly authorized releasing this reviewed RC6
using its checked-in validation gates before integrating the separate,
uncommitted strict specification-assurance framework. Framework integration is
deferred until after owner validation. This is a release-specific exception,
not a claim that the newer assurance checker has passed or a permanent waiver.
