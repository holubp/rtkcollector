# NTRIP RC4 Transport Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans or subagent-driven-development task by task. Track each checkpoint below.

**Goal:** Ship RC4 with system-trusted TLS and explicit plaintext NTRIP in both distributions, with accurate profile and dashboard presentation.

**Architecture:** Keep transport selection in profile security policy and pass it unchanged to the shared connector used by sourcetable, correction and upload clients. Retain legacy unsafe verification values only as blocked migration markers; remove the trust-all connection path. Display the selected transport as profile metadata, separately from service connection state and error messages.

**Tech Stack:** Kotlin, Android Compose, Gradle, JUnit, GitHub Actions.

**Spec:** User-approved RC4 transport requirements in the 2026-09-25 request and canonical `docs/specification/` updates in this change.

## Global Constraints

- TLS requires system certificate trust and hostname verification; no fallback to plaintext.
- Explicit plaintext is supported for correction, sourcetable and upload in both distributions.
- Existing explicit transport choices persist; legacy unsafe TLS cannot connect until the user chooses TLS or plaintext.
- Receiver recording remains independent of NTRIP failures.
- RC4 is a debug sideload prerelease; the Play AAB needs separate Windows signing and verification.
- Play submission remains blocked pending resolution of Google's modern-cryptography
  requirement for transmitted credentials and GGA; RC4's Play variant still includes
  the requested explicit plaintext mode.

## Review Focus

- Import an old unsafe TLS profile: it remains blocked until an explicit new choice is saved.
- Select plaintext in a Play build: the profile, runtime intent and socket all retain plaintext.
- Fail TLS certificate or hostname checks: the connection fails without a TCP retry.
- Select plaintext with GGA: the profile warning mentions the position.
- Reopen the home screen while disconnected: profile transport still appears without an error banner.
